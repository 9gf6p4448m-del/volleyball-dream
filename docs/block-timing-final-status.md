## 四、誠實註記

### 4.1 款 3 警報器
本卷過程中**紅過一次又自己回來**：段 1 落地後 gap 掉到 1.8pp（紅）、段 2 落地後回到綠、
段 3 定案後 +14.4pp。裁定 0 乙案預先簽准了這段紅燈。門檻本身**一格未動**，
新門檻數字待 Sawmah 確認。

### 4.2 commit 牆整體變弱（併同觀察，非驗收項）
段 1 拆掉「站著擦球」之後，commit 的攔網接觸從 173 掉到 54（40 局）、
`tandem-block-probe` 量到牆的「進帶%」只有 3.3%、牆上人數 p50 = 0。
**但攻方每球得分反而從 0.677 降到 0.661**——防守整體沒變弱，變的是「攔網」這件事
從「站著擦到」回到「真的跳起來攔」。這條屬**難度位移**，依裁定歸難度重校卷處理。

### 4.3 tool 解封條件未達成（口徑已換）
把 `TUNING.TOOL_CHANCE` 掃到 0.35 實跑 20 局
（`node tools/t10-4b-blockout-probe.mjs 20 0.18 0.12 0.35`），**tool 扣球仍為 0/局**。
卷前的關閉理由是「牆起跳時序為正常球路而生，瞄手意圖連結率 <10%」；
現在的阻塞點換成「**牆很少出現在球路上**」（進帶 3.3%）——`toolBlockerFor` 找不到目標。
⇒ 本卷**不解封**，理由據實記錄。原「連結率 <10%」那組口徑的探針本卷未能重建，
未以任何重造的模型去宣稱該指標已改善（`02 §6.1` 條 4）。

### 4.4 段 3 降級機制的處置
機制（`laggedZView` ＋ `OUTER_LZ`／`OUTER_LX`／`OUTER_LAG_MUL`）**留在碼裡但出廠關閉**，
不是沒做。掃描時另外抓到一個坑並寫進常數註解：`OUTER_LZ` **不能設在快攻助跑起點
（3.0）以內**——設 2.9 會連快攻手一起降級，款 3 gap 實測翻成 −7.3pp。
