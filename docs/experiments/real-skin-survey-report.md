## 0. 結論

推薦方案 3：CPU 依姿勢位移（implicit skinning 式的碰撞修正）當主幹。它單獨拆掉了「上臂剛性垂下就穿胸」這條衝突：
- 20k K4b 的 S2 從 167/10.2 降到 1/1.8；K4a 從 422/9.4 降到 2/0.0；5k 九幀 S2 全綠。
- S11 讀數完全不變，因為軀幹頂點一個都沒動。
- S13 維持 ≤0.50。

還沒解的是 S1（腋下要有過渡帶）↔ S14（上臂 t≥0.3 的皮要剛性）。這是「過渡帶放在哪裡」的幾何定義衝突，四個方案都無法在不改 S1 或 S14 定義的前提下解掉，需要使用者裁定（見 §7）。

DQS 只解了 K1a 高舉時的胸口塌陷，卻新增關節膨脹（S14 大紅），也解不了下垂穿入，所以不適合當主解。

## 2. 方案 1：DQS／LBS-DQS 混合

**原理**：各骨的剛體變換改用對偶四元數加權後正規化，混合結果仍是剛體，所以沒有 LBS 的糖果紙和塌陷，代價是關節彎曲處會膨脹。

**依據**：
- Kavan 2008：https://users.cs.utah.edu/~ladislav/kavan08geometric/kavan08geometric.pdf
- three.js 沒有內建，相關 issue 仍開著：https://github.com/mrdoob/three.js/issues/20324
- 膨脹問題的說明：https://la.disneyresearch.com/publication/skinning-with-optimized-cors/

**原型**（proto/skins.mjs、proto1.mjs）的自我檢查（logs/dqs-check.log）：
- LBS 分支與 lib.skinPositions 逐值相同，差 0。
- 單骨頂點上 DQS 與 LBS 差 3.7e-18 m。
- 多骨頂點最多差 11.2 cm，證明 DQS 真的在作用。

5k 的結果同方向，見 logs/p1-*.log。

- **能解**：K1a 塌陷（左臂 86/8.3 → 17/1.1，在 R9 上限內）。
- **不能解**：下垂穿入（K4b 78/3.9，上限 30/2.0），以及 S1。
- **新增問題**：膨脹，S14 點數變成 3–5 倍。截圖 K1a-左臂胸口近拍 第 3 格可以看到腋下鼓起。
- **代價**：
  - CPU 版每人每幀：5k 0.46 ms、20k 2.03 ms（LBS 分別是 0.22、0.68 ms，node 桌機）。14 人在手機上估計不可行（未實測）。
  - GPU 版要動 shader，違反 S12，需要使用者另外同意。
  - 量尺必須同步改成 DQS，這件事要走 §2.1。
  - 工時估 2–3 天。

## 3. 方案 2：換 CC0 底模

**原理**：換成專業做好布線與權重的人體模型，再把動作重定向到它的骨架。

**依據與授權**（已查原文）：
- Quaternius Universal Base Characters：CC0，平均 13k 三角形，Humanoid rig，有 glTF，可商用。https://quaternius.com/packs/universalbasecharacters.html
- MakeHuman：匯出物為 CC0。https://static.makehumancommunity.org/oldsite/faq/can_i_sell_models_created_with_makehuman.html
- Mixamo：不是 CC0，是免版稅，但受 Adobe 條款約束，官方定位是 technology preview。https://community.adobe.com/questions-696/mixamo-faq-licensing-royalties-ownership-eula-and-tos-589400

**預期能解**：S1、S2、S13、S14 都有機會一起解。這一點未實驗；Quaternius 仍是 LBS，效果取決於它的布線品質。

**代價**：
- Modly 那位選手的臉、身形、衣褶全部沒了；地標、部位上色、背號掛法都要重做。
- 工時估 5–10 天。
- 與 S12 相容。

**原型**：沒做。要先下載資產、重定向骨架、重做地標，不屬於快速原型。

## 4. 方案 3：CPU 依姿勢頂點位移（不用 morph）

**原理**：先照常做 LBS，再修正手臂頂點：
1. 離線把綁定姿勢的軀幹烘成 SDF（格距 1.5 cm）。
2. 執行期把手臂頂點轉回軀幹三骨的綁定空間，查 SDF。
3. 穿入軀幹的頂點沿梯度推到表面外 4 mm。
4. 沿網格鄰接平滑 6 輪。

位移只加在手臂頂點，所以 S11 不受影響。這等於用 SDF 自動產生 PSD 範例，不必手雕、也不用 morph target。

**依據**：
- Vaillant 2013：https://rodolphe-vaillant.fr/entry/31/implicit-skinning-real-time-skin-deformation-with-contact-modeli
- Lewis 2000 PSD：https://www.scribblethink.org/Work/PSD/PSD.pdf
- 「腋下雙輔助骨」：未查證，沒找到可引用的來源。它本質仍是 LBS，會撞上同一組互斥，所以沒另做原型。

**原型**：proto/corrective.mjs、proto3.mjs。基底用 wip4 烘焙器（c05670c1），AUX.W0=0，UPPER_RIGID_T 試了 0.3／0.5／0.7。

5k、t≥0.7＋碰撞修正（logs/p3-rigid07-5k.log）：S2 九幀全綠；剩 S14 最大值超出上限 0.2–3.4 cm（K1a 左、K1b 右、K3b、K4a、K4b 左），以及 K1b 的 S1 P99 7.61。

- **能解**：下垂穿入，而且能和上臂剛性共存，S11、S13 都不變。截圖 K4b 兩張的第 4 格沒有蹼，也沒有穿胸。
- **不能解**：S1 ↔ S14。另外試了 PBD 放鬆肩帽帶，K4b P99 從 23 降到 11，但到不了 6（logs/p3-rigid03-relax*.log）。
- **已知缺陷**：
  - K1a 近拍第 4 格，胸側球衣有摺碎的尖角。
  - 20k 的 K2b、K4c 右臂各剩 1–3 點、約 2 cm 的穿入。
- **代價**：
  - 每人每幀：20k 3.5–8.4 ms、5k 2.6–4.0 ms（node 桌機），還要再加一次 CPU LBS。14 人全開，手機估計不夠。
  - SDF 約 0.4 MB，可以離線烘焙（符合 S8）。
  - 需要 S12 例外：每幀寫入 position，或改成 CPU 蒙皮＋一般 Mesh。不動 shader、不用 morph，量尺也能直接量到畫面用的那份資料。
  - 工時估 3–5 天。

## 5. 方案 4：腋下重新布線或加密

**原理**：在腋下加邊迴圈（edge loops）。

**依據**：只有業界討論，不是學術文獻。例：https://blenderartists.org/t/shoulder-deformation-tutorials/558618

**預期**：
- 加密不能降低 S1 的拉伸倍率。同一條帶子被拉開，切成幾個三角形，倍率都一樣；加密只能讓拉伸分布更均勻、壓低 P99。
- 也改變不了「過渡帶只能放在 t<0.3」這個限制。
- 適合當方案 3 的輔助，讓凹痕更平順。

**代價**：
- 要在 Blender 做 retopo，本機目前沒裝 Blender。
- 改 glb 會讓所有凍結集合失效，量尺必須重凍（要走 §2.1）。
- 工時估 3–6 天。
- 與 S12 相容。

**原型**：沒做，因為量之前得先重凍量尺。

## 6. 推薦排序

1. **方案 3 碰撞修正，搭配寬過渡帶（上臂 t≥0.7 才剛性）**：實測中唯一能讓上臂剛性與下垂不穿胸同時成立、又不拖動軀幹的方案。
2. **方案 2 CC0 底模（Quaternius 優先）**：唯一有機會一次解掉全部衝突，但外觀要全換，工時也最長。
3. **方案 4 網格加密**：只適合當方案 3 的輔助。
4. **方案 1 DQS**：解一條（塌陷）又多一條（膨脹），還要改 shader。如果需要這類方法，可改看 Optimized CoR（https://dl.acm.org/doi/10.1145/2897824.2925959），它同樣要 shader，這次未做原型。

## 7. 需要使用者裁定

1. **主線**：走方案 3（保留 Modly 外觀，需要 S12 例外），還是方案 2（外觀全換）？
2. **S12 例外的做法**：每人一份 position 每幀寫入，還是改成 CPU 蒙皮＋一般 Mesh？
3. **S1 ↔ S14 怎麼處理**（甲、乙都會讓通過機率上升，依 §2.1 需要逐條同意）：
   - 甲：S14 改從 t≥0.5 或 t≥0.7 起算。
   - 乙：高舉幀的 S1 放寬到 P99 ≤8。
   - 丙：兩條都不動，接受留紅。
4. **手機效能分級**：可否只對近景球員或 5k 模型開修正？必須符合鐵律 2，只能固定分級或走 URL 參數。
5. **若走方案 2**：用 Quaternius 還是 MakeHuman？球衣短褲改用頂點上色重做可以接受嗎？
