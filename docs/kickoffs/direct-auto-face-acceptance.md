# 接球自動轉身（三種模式試用）：驗收條件（2026-09-25 動手前凍結）

使用者裁定（2026-09-25）：接球時身體轉向場內目標，提供三種模式讓使用者試用後選一種保留：
- **全自動**：朝向場內目標，不設轉角上限。
- **半自動**：朝向場內目標，但相對「正對球網」最多轉 45°（Claude 建議保留此款）。
- **手動**：維持現況（朝向由朝向區決定，觸球時自動迎球 ±35°）。

三種都保留左右滑 ±8° 微調。場內目標固定為舉球區中心 (x 0, z 1.6)。

做法：**模擬核心不動**。操作層在「動作選單為墊球、球在場上」時，把送進模擬的朝向指令改成目標方向（半自動夾在 ±45°）。朝向指令本來就是錄影的一部分，所以決定論與重播不受影響，`SIMULATION_VERSION` 維持 `direct-v5`。

動手前探針（worktree、真實 `stepDirectGame`，朝向指令直接給目標方向）：玩家站在 11 個場邊／底線外位置 × 球往場外漂移 0／1／2 m/s，球從 3.5 m 落向平台，按墊球時機第 20–44 tick。救回場內（主動前臂或手觸球、落在 z 0.5–8 m、|x| ≤ 4 m）：手動 13/33、半自動 45° 25/33、全自動 29/33。

本檔凍結後，任何會讓通過機率上升的修改（降門檻、縮案例、改量測方式）須先寫明原標準錯在哪，並取得使用者對該條的明確同意。

## 操作層（純函式，單元測試）

- **A20a 朝向計算**：新模組提供 `autoFaceAim(mode, player, ball)`。
  - `manual`：回傳 `null`，不改朝向。
  - `full`：回傳從玩家位置指向 (0, 1.6) 的單位向量。
  - `half`：同上，但角度夾在正對球網（`{x:0, z:-1}`）的 ±45° 以內。
  - 球不在場上（`ball.active` 為 false）時，三種都回傳 `null`。
- **A20b 套用條件**：只有「動作選單為墊球」且非回放時才改寫指令的朝向；選扣球等其他動作時，指令與現行逐值相同。手動模式下，所有指令與現行逐值相同。

## 真實指令鏈（模擬核心 + A20a 函式）

- **A20c 救球率**：同上述探針設定，但每個 tick 的朝向由 `autoFaceAim` 依當下玩家與球的位置算出（玩家起始面向球網）。門檻：
  - 全自動救回 ≥ 25/33
  - 半自動救回 ≥ 21/33
  - 手動救回 = 13/33（和現行完全相同）
  - 且全自動 ≥ 半自動 > 手動
- **A20d 不是保證接到**：全自動下，所有「按鍵時機 × 情境」組合中，救回場內的比例 ≤ 60%。時機與站位錯了，照樣會噴。

## 畫面

- **A20e 設定選項**：「訓練設定」新增「接球轉身」下拉：手動（預設）／半自動 · 45°／全自動。瀏覽器治具在三種尺寸驗證：選項存在；選全自動並餵球後，玩家朝向在觸球前轉向目標（`player.aim` 與目標方向的夾角 < 10°）；選手動時朝向不被改寫。

## 整體

- **A20f** `npm test` 全綠（既有測試一行不動）、`npm run build` 成功；瀏覽器治具預設／`--assist`／`--motion`／`--pass` 全部 PASS；`git diff` 中 `src/sim/` 零改動。
- **A20g 鑑別力**：A20a／A20c 在實作前紅（模組不存在屬於前置條件，另以「全部回傳 null」的空實作確認 A20c 的全自動、半自動門檻會紅）。
