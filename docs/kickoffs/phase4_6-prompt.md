## 2. 重演舞台（`src/render/replayStage.js`，新）

### 2-1 規格

- **全編制**：十二人＋球＋場地線＋網。人物與球動畫由 Intent 流驅動既有 animator。
- **場館＝不做**。暗場＋光池（球場範圍的地面光池，人與球是唯一亮點）。
  理由入卷：冠軍點發生在冠軍館，用常規館幾何＝錯棚；搬冠軍館穹頂＝為一顆球扛
  全遊戲最重場景。**回放是記憶，不是現場重現**——與 ritualStage 聚光／幕三坦白
  光帶／夜賽剪影同一套美學語彙。
- **前例遵循**：`ritualStage.js`／`beatStage.js` 範式——獨立 renderer/canvas、
  WebGL 失敗退化（退化行為見 §2-3）、dispose 慣例齊全。
- **模組重用**：`arena/court/players/geoAnimator/ballView` 理論上可重用，**重用範圍
  ＝本輪最大工程判斷，實作端裁量，如實記錄於結案快照**（哪些直接吃、哪些另建、為什麼）。
- **重演契約**：快照＋同序 Intent 重演＝**逐格一致**（與賽中 `s.replay`／情蒐 tape 同契約，
  決定論背書）。重演過程**零 sim 寫入**、不進 Intent/rand 路徑。

### 2-2 播放控制

- 直接消費 4.5B 演出時鐘（`ui/presentation.js`）：`createBeatTimeline`／`driveTimeline`
  ——牆鐘 rAF、sim 凍結相容、`finish()` 跳過＝與播完終態逐值一致。
- 必備：播放／暫停／跳過；reduced-motion＝不進舞台，退化為 §2-3。

### 2-3 退化路徑

WebGL 失敗或 reduced-motion → 不建舞台，退化為**該球的文字紀錄卡**
（誰發球→誰舉→誰扣→結果），不留空白、不報錯。

### 2-4 效能（**非閘門，資料收集**）

Sawmah 已裁定 FPS 非顧慮，不預設降規檔位。但原型第一版仍須在真機量一次，
**分三段記錄：進重演前／重演中／退出後**——順手替 4.5B 遺留的「35FPS 場景未定位」
懸案收定位線索，數據落結案快照。

若真機出現問題才啟動降規，序為：陰影 → 尾跡/塵土粒子 → 對手六人降剪影材質 → 幀率上限。
**降規一律只走 URL 參數，不得自我降級特效**（架構鐵律／Phase 0 精神）。

記憶體：dispose 紀律照既有前例，離開典藏牆即拆（第二套 renderer/材質/幾何不得殘留）。

## 3. 典藏資料層 — 固定四槽

### 3-0 容量探針（**開工第一步，硬要求**）

實測單筆 `finalRally` 序列化位元組數（`JSON.stringify(finalRally).length`）。
單筆是 30KB 還是 500KB 決定四槽在 localStorage 下安不安全——**這是唯一可能翻掉
四槽案的變數，不得估算，先量再做**。數據落結案快照。

若實測顯示四槽超出安全預算：**停手回報，不自行縮減槽位或改壓縮方案**，
由 Sawmah 裁定（可能結論＝退回單槽 A 案）。

### 3-1 槽位定義

| 槽 | 內容 | key |
|---|------|-----|
| 0 | 冠軍點（現有資料，不動） | 沿現行 |
| 1 | 第 1 屆天鷹掛點場最後一球 | 屆數 |
| 2 | 第 2 屆天鷹掛點場最後一球 | 屆數 |
| 3 | 第 3 屆天鷹掛點場最後一球 | 屆數 |

- **上限恆為 4 筆**，屆數即 key，**永不覆寫**。
- **錄該場最後一球（勝負點）**。決定論下「最精彩」定義不出來；最後一球明確、
  戲劇性最高，且與宿敵三幕賽後演出同一拍。
- **勝敗皆錄**（拍板明示）。幕一碾壓的敗點是三幕結構的視覺回收；只錄勝場等於把
  宿敵線前半段從典藏刪掉。入口走自選（§5），敗場回放不會變成懲罰。
- **該屆止步旁觀未實戰天鷹＝該槽空**；空槽不出現（顯示哲學：不給玩家看空欄）。

### 3-2 錄製掛點

沿 4.5A `nationalLadderFor` 的天鷹逐屆掛點（第 1 屆決賽／第 2 屆準決賽／第 3 屆決賽）；
判定「本場對手＝sky-hawk」即在場末寫入該屆槽。錄製走既有 VCR 錄製規格
（快照＋Intent 流），**不新增 sim 事件型別**。

### 3-3 存檔相容

`finalRally` 由單筆改槽結構＝**不寫回退相容層**，沿憲法縫隙 4 精神（刪檔重開）。
舊存檔進入典藏牆時視為無資料（入口卡不出現），不得報錯。

## 4. 自動導播（`src/render/replayDirector.js` 或等價）

### 4-1 腳本骨架（一顆球從發到落）

| 段 | 鏡位 |
|---|------|
| 發球 | 發球員背後中景 |
| 飛行／接發 | 跟球廣角 |
| 舉球 | sset 語彙的半場回望 |
| 決定性一拍 | sig 三構圖依攻擊者位置擇一（OH／MB／OPP）＋慢動作（重用 slowUntil 機構） |
| 落點收尾 | 貼地低機位，重用第四道招牌演出「邊線是我的」構圖 |

鏡位語彙全部取自既有資產：`cameraRig.beatShot` 四模板＋sig 三構圖＋sset 模式。
**不新增第五模板**（沿 4.5B 矩陣紀律）。

### 4-2 硬要求：導播決定論

同一顆球每次觀看，鏡頭腳本**逐格一致**。切鏡點由 **Intent 流的事件型別驅動**
（SERVE／TOUCH／SET／SPIKE／BLOCK／落點事件），**不吃時間隨機、不吃牆鐘抖動**。
測試背書：同一 finalRally 連跑兩次，導播決策序列 `deepEqual`。

理由入卷：回放要能當敘事素材反覆使用（宿敵典藏尤其），鏡頭必須是「被導演過的」
而非每次不同；且與 sim 決定論同一條紀律。

## 5. 典藏牆入口卡（careerScreen 生涯結算流程）

### 5-1 現況與改動

現況＝一行靜態文字（「🎬 關鍵球典藏：第 N 屆冠軍點，已永久收藏」），點不開、不會播。
改為**四格典藏牆入口卡**：

- 四槽縮圖並排，每格＝靜幀＋標籤（例：「第 1 屆・決賽・敗」「冠軍點」）
- **空槽不出現；四槽全空＝整張卡不出現**
- 點任一格 → 進重演舞台 → 播完**回結算流程原位**，不打斷後續節拍
- 位置＝現行「關鍵球典藏行」原位（三屆定格→生涯數據→招募全記錄→**此處**→謝幕→
  送別→畢業儀式→「第一章・完」）

### 5-2 不自動插播

拍板明示不走 B/C。畢業結算已經很長，強制插播＝把儀式變成關卡；典藏牆的情感邏輯是
「你自己回去翻」。

### 5-3 靜幀來源（實作端二選一裁量）

1. 首次進入典藏牆時，各槽以重演舞台跑一幀離屏渲染取縮圖
2. 退化為純文字格

**不得為此新增任何錄製資料。** 選擇與理由記入結案快照。

## 6. 小白事件二「位置示意」（`n2Arc.js` 演出位）

### 6-1 拍板：B 示意圖層，不吃重演引擎

技術理由入卷：事件二觸發源＝`settleCareerMatch` 賽末掃描 `scanChaseLost` 推導的**統計**
（`lbChase`/`lbWho` 兩個數字），**沒有那顆球的 rally 快照**。要重演須為劇情事件新增
整條錄製鏈（sim 事件流標記＋賽中觸發快照＋新存檔欄位），擴散不成比例。

設計理由：事件二的敘事點是**「位置讓出來了」**，不是「他撲得多慘」。重演把注意力給動作，
示意圖給的是空間。

### 6-2 規格

- **靜態俯視半場圖**：自由人起點 → 撲救路徑（虛線）→ 落地點；
  **讓出的區域＝空白亮區**（不是紅色警示，是「沒有人」）
- 對手球落點標記打在亮區內
- **固定構圖、不讀真實座標**（沒有座標可讀）——示意圖是手繪規格
- **三版共用同一張圖**：
  - 上場版（主體＝小白）
  - 師徒版（玩家＝L，主體換成你）
  - **場邊保底版同樣給圖**（拍板明示）：改標多點落地痕（他數落地的球）
- 交付形式：SVG 或 canvas 繪製皆可，零圖檔資產（沿零模型檔／零音檔路線）
