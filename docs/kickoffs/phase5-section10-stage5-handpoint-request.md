## 一、卡在哪

裁定書 v3 §一 補列白名單三項。實作端開工前逐項查核：

| # | 白名單項 | 零新常數做得到嗎 | 依據 |
|---|---|---|---|
| 1 | `volume.kind`：`'cylinder'` → `'sphere'` | ✅ | 純結構變更 |
| 2 | `cy` 啟用（垂直軸心開始有意義） | ✅ | 手點 y 用**既有量**：扣球／跳舉＝`spikeReach(球員, 體力乘數)`｜魚躍＝`DIVE_MAX_Y`｜其餘＝`standingReach + SET_CEILING_BONUS`。這三個就是**現行圓柱的天花板 `top`**，不必新增任何數字 |
| **3** | **手點 x/z 由動作相位決定（不再等於 `actor.x`／`actor.z`）** | **🔴 做不到** | 見下 |

### 1.1 為什麼第 3 項做不到

**`src/sim` 裡沒有任何人體幾何量。** 實作端已全檔查核：

- `constants.js`：只有**球場**（長寬、網高、攻擊線…）與**球**（半徑、重力、彈性…）
- `player.js`：只有 `standingReach`（＝身高 × 1.31，**過頭指尖摸高**）、
  `jumpHeight`、`spikeReach`、`blockReach`、`moveSpeed`、`defenseRange`（死碼）

**沒有額前高度。沒有體前偏移。** 一個都沒有。

### 1.2 憲法補充 §1.3 的表只給了「可及半徑」，手點欄是**質性描述**

| 動作 | §1.3 的手點描述 | 實作端缺什麼 |
|---|---|---|
| 接球 | 依據欄：「平台接觸點**在體前**，不在指尖」 | **體前水平偏移是幾公尺？** 無現成量 |
| 舉球 | 「手點＝**額前上方**」 | **額前高度是身高的幾倍？** 無現成量。`standingReach` 是**過頭指尖**，不是額前 |
| 扣球 | 「手點**吃跳躍位移**」 | ✅ 不缺——`spikeReach` 就是它，**而且只是垂直** |
| 魚躍 | 給絕對值 ≈ 2.0 m | ✅ 垂直有 `DIVE_MAX_Y` |

⇒ 任何實作端自己挑的體前偏移／額前高度都是**新常數**，且必然是對著現值反推
⇒ **撞協議 1**（「不得沿用現值反推」）。
依裁定書 §2.6-d（**裁定權不下放治具**），實作端**回報，不自行代換**。

## 二、附帶發現：一處文件層的不一致（可能是補列時的擴寫）

**憲法補充 §1.2 對「動作相位」的自帶註解，只講垂直**（原文）：

```
觸球成立 ⟺ |球心 − 手點| ≤ 該動作可及半徑 + BALL.RADIUS
手點由動作相位決定（起跳中的手點隨跳躍曲線上移）
```

括號裡的例子是**「隨跳躍曲線上移」＝純垂直**。

而**裁定書 v3 §一 補列的第 3 項寫的是 `x/z`**。

⇒ 兩者不一致。實作端不預判哪個是本意，但這決定了本題該怎麼裁。

## 三、兩個選項（實作端不挑）

| | 作法 | 代價 | 之後怎麼走 |
|---|---|---|---|
| **甲** | **裁定端補兩個目標值**：①接球的體前水平偏移 ②舉球的額前高度（比照 §1.3 的方式，從真實排球導出，不從現值反推） | 要出兩個數字 | 三項**一次換上**，符合「段 1 之前一次換上」 |
| **乙** | **第 3 項改判為「垂直相位化、水平不偏移」**（手點 **y** 由動作相位決定，x/z 仍為 `actor.x`／`actor.z`）——與憲法 §1.2 的自帶註解一致 | 白名單第 3 項文字要從 `x/z` 改成 `y`（走 §一 的「補列並留痕」同一程序） | **零新常數、可立刻執行**，一次換上 |

### 3.1 實作端明確**不建議**的第三條路

**「先做 1+2，之後再補 3」** ⇒ 會導致**重新量收斂前基準兩次**，
而那正是裁定書 §4.2① 反對「50% 一步跨過去」的同一個理由（歸因）。
若裁定端傾向分兩次，請明示，實作端會照做但要求兩份基準都登記。

### 3.2 兩個選項對後續的影響差異（供判斷，非本端立場）

- **甲**會讓可及球體真的離開球員腳下（接球的球體中心跑到體前）
  ⇒ 走位的語意跟著變（「站到球正下方」不再等於最佳位置）。這是**更貼近真實**，但影響面較大。
- **乙**的球體中心仍在腳的鉛直線上，只有高度隨動作變
  ⇒ 與現行走位邏輯相容，換模型的行為漂移較小、較容易歸因。
