## 二、死結的結構（**全部讀程式碼得出**，非轉述）

死結是**三層串聯**。只修任何一層或兩層，分歧率都不會動。

### 第一層：roll 的雜湊鍵裡沒有「人」

`src/sim/ai.js:1598-1600`：

```js
const { score } = game.match;
const roll = hash01((score.A * 1009 + score.B) * 613 + 71 + (game.seed ?? 0));
const best = pickByWeights(entries, scores.map((v) => v / sum), roll);
```

雜湊鍵 ＝ **比分 ＋ seed**，無任何 per-player 成分（對照：同檔其他 roll 都帶 `idHash(playerId)`）。
⇒ 同一分內不論誰呼叫，`roll` 逐值相同 ⇒ 必然選同一個人。

當初的兩個要求（`ai.js:1592-1597`）**兩個都還成立、不得違反**：
1. **與二傳的 roll 不同源**——同源＝100% 賭中＝直接讀答案（二傳用 `flightId * 977 + 131`）。
2. **一個 rally 內恆定**——用 `flightId` 當鍵會讓賭注在觸球那一刻無故換人，
   chase 段被當成「改判」白付 `REPLANT_TICKS`。

### 第二層：第二名攔網手根本不 roll

`src/sim/ai.js:1651-1660`：

> `team`／`template`＝團隊級——**建計畫仍是單一事件**：第一個解鎖的人建，其餘人共讀。
> （read 的解鎖吃自己的 `reactionTicks` ⇒「誰先解鎖」本來就決定了整份計畫的內容與時點，
> 拆成各建各的會連建計畫的時機與輸入都變 ⇒ **本步不動這一層**。）

賭注位置 `x` 是 `BLOCK_PLAN_CARRY` 的**第一個欄位**（`ai.js:1675-1677`）：

```js
const BLOCK_PLAN_CARRY = ['x', 'enterTick', 'jumpTick', 'jumpAt', 'replantUntil',
                          'pendingX', 'blind', 'seen', 'hand'];
```

`blockPlanFor`（`ai.js:1679-1690`）在每人**第一次取用時**逐 key 從 `template` 複製，
之後只由本人步進 ⇒ 第二名攔網手的 `x` 是**抄來的**。
唯一 sim 呼叫點是 `blockAimX`（`ai.js:1647`），一次呼叫服務**全隊**（`aiState.blockPlan` 是單一團隊級欄位，`ai.js:244`）。

### ★ 第三層（本次新查出，關鍵）：`x` 在 rally 內逐 tick 恆等

`ai.js:1608-1616` 的 `mix` 分支現在是**活的**：`blockRead.js:174` `AIM_CROSSING_MIX: 1`。
mix=1 代入 `const x = a.x + (midX - a.x) * mix` ⇒ **`x = midX`**，攔網手自己的位置 `a.x` 被完全消掉。

而 `midX` 只由 `best.kind` 決定：`setAimFor` 對每個 kind 回傳**寫死的常數**
（`approach.js:39-57`：`quick → lx 0`、`bquick → −2.2`、`left → −3`…），
再經 `localToWorld` → `spikeAimsAt` → `netCrossingX` 取中點。與球的位置、時間、球員狀態都無關。

**後果：`kind` 在 rally 內恆定（第一層）⇒ `x` 在 rally 內恆定 ⇒ 連「在不同 tick 求值」都產不出分歧。**
這一層否決了所有「靠相位差／掉隊自然湧現分歧」的做法（見 §五 方向 C）。

### 這一層已經拆過一半（重要）

攔網分工卷 step2b（2026-07-31）已把 `seen`／`jumpTick` 等改成 per-blocker 步進
（`ai.js:1664-1673`），明文說這是**「個別騙得到某一名攔網手」在結構上可表達的那一刻**
——組合攻擊的交叉／夾塞／時間差要騙的就是這個。`cover`／`chase` 刻意不進 CARRY（`:1682-1683`）。

**唯獨「往哪裡賭」（`x`）沒跟著拆。** 本卷要動的就是那條刻意留下的邊界。

現存 per-blocker 通道六條，實際**只剩「漏 tick」一條是活的**：`outerLag`（`ai.js:1869-1872`）
因 `OUTER_LAG_MUL=0` 是死的、`jumpAt`／`hand` 是團隊級、`cover`／`chase` 不影響瞄準。

## 四、待裁的題

### 題 0（應該最先裁）：憲法 §2.2 的「選定一名攻擊手」是什麼意思？

權威出處＝`docs/phase5-section10-RESOLVED-supplement.md` §2.1（`:104`）／§2.2
（該檔 `:165-168` 已自行更正了「憲法 §零」的錯誤指涉）。
§2.2 的【判】寫「選定**一名**攻擊手」——**沒說是「每隊一名」還是「每人各一名」**。

- 讀作「每隊一名」⇒ 本卷整個提案違憲，到此為止。
- 讀作「每人各選一名」⇒ 本卷是在補完它，現況反而是實作偷懶。

**這句話怎麼讀，決定這一卷存不存在。** 其他題都在它之下。

⚠ **釐清（read-back 指出的混淆）**：題 0 裁的是「**該不該修**」，不是「**診斷對不對**」。
§二 的三層機制是讀程式碼得出的事實，題 0 無論怎麼裁它都成立——
裁成「每隊一名」的意思是「這個結構是**刻意的設計**、已知並接受」，
而不是「§二 描述錯了」。兩者不要混在一起讀。

### 題 1：要不要讓兩名攔網手分開賭？（難度題，不是工程題）

- **可能變強**：兩人守不同的線 ⇒ 覆蓋面變大 ⇒ 攻方更難找空門。
- **也可能變弱**：兩人各賭一邊 ⇒ 沒有「兩人都賭對」時的雙人牆 ⇒ 單人攔比例上升。

**哪一個佔上風現在沒有數字，不得憑感覺拍。** 建議先做 §六 的量測，拿到攻方得分率位移再裁。
（C3 難度裁定＝「維持現狀」，真人第 1 屆體感 OK。本卷若讓難度顯著位移＝重開那道已關的卷，
這是拍板前要知道的代價。）

### 題 2：如果要分歧，分歧度要多少？

「兩人完全獨立抽」是最極端的一端（分歧率 ＝ 1 − Σpᵢ²）。中間還有
「第二人以機率 q 跟隨第一人、1−q 自己抽」這種帶旋鈕的做法。
本專案偏好**零新常數**（卷五 B 快就是零新常數落地），但旋鈕讓難度可無痛回退。

## 五、可能的方向（**假說，未驗，不得當事實用**）

### 方向 A：`x` 退出 `BLOCK_PLAN_CARRY`，改成各自求值 ＋ roll 帶 pid salt

第二名攔網手首次取用計畫時不抄 `template.x`，改自己呼叫一次 `blockSetterTendency`，
roll 鍵加上自己的 pid。**三層一起解**（第一層 salt、第二層不抄、第三層因為 kind 不同所以 x 不同）。

**與題 2 的關係（read-back 指出的漏講）**：方向 A 就是題 2「完全獨立抽」的那個**極端端點**
（q = 0）。也就是說**選了方向 A 等於已經回答了題 2 的一半**——若之後想要旋鈕，
是在方向 A 的基礎上加一道「以機率 q 跟隨第一人」的判斷，不是另一條路。
方向 B 同理（salt 換成解鎖順序，分歧度仍是 q = 0）。

- 優點：語意直白（「各賭各的」），改動集中在 `ai.js:1599` 與 `blockPlanFor`。
- 風險：`x` 與 `pendingX`／`replantUntil` 有耦合（改判路徑 `ai.js:1882-1898`，
  `REPLANT_JUMP_M=1.0`／`REPLANT_TICKS=12`）——**第一次取用算不算「改判」？**
  算 ⇒ 第二人一出場就白付 12 tick（幾乎確定是錯的）；不算 ⇒ 要確認 `replantUntil` 初值不失效。
  **動手前必須查清楚這一點。**
- 風險：踩到 §三.1 的護欄名稱、§三.4 的遍歷順序缺口。

### 方向 B：不傳 pid，用「解鎖順序」當 salt

每人解鎖 read 的 tick 本來就不同（吃各自的 `reactionTicks`）⇒ 用「他是第幾個解鎖的」當 salt，
不必把 pid 傳進 `blockSetterTendency`，護欄名稱不用改。

- 風險：兩人可能**同一 tick 解鎖**（並列）⇒ 退化回同一個 roll。
  **要先量「兩人解鎖 tick 相同的比例」**，太高則此方向不成立。

### ~~方向 C：只讓「落後的那一個」分歧~~ ← **已被 §二 第三層否決**

原構想是靠 step2b 的「掉隊」自然產生分歧。但 `AIM_CROSSING_MIX=1` 讓 `x` 在 rally 內**逐 tick 恆等**
⇒ 掉隊的人回來重算也得到**同一個 x**。**不改 roll 就不可能有分歧**，此方向不成立。
（若替它補上 salt，它就退化成方向 A 的子集。）

### 方向 D（Claude.ai 可補）：不動賭注，改動兩人的**站位分工**

讓同一個賭注在兩個人身上長出**不同的守備範圍**（例如一個守直線、一個守斜線）。
繞過整個 roll 問題，也不碰反作弊護欄。**未評估，列出來供討論。**
