## 任務清單

### 1. 年級系統(資料層,地基級)

- `STARTER_DEFS`(roster.js)全員補 `grade` 欄位(1/2/3):
  - **大山(MB/隊長)=3 年級**
  - 另選**一名兩翼(OH/OPP)、戲份最少者=3 年級**(檢視 events.js 台詞量後定,
    定案後將人選回填 decisions-RESOLVED.md Q1 段)
  - 阿哲(S)、小守(L)**必為 1-2 年級**(功能核心不得第 1 屆畢業)
  - 玩家=1 年級(高中章固定 3 屆)
- `RECRUIT_DEFS`(recruitment.js)七人補 `grade`:
  - 配比原則:**招募條件越苛刻者,年級越低**(長線投資不被年級懲罰);
    至少 1 名三年級(展示「只能用一年」的取捨)、至少 2 名一年級
  - 年級與來源隊 squad 名單同一人一致(naming.test 把關擴充)
- 對手 `squad`/`ace`(opponents.js)補 `grade`:七隊 ace 至少 4 名=3 年級
  (第 2 屆換臉的敘事量),其餘配比自然分布
- 賽季推進時全員 `grade` +1;3 年級季末=畢業

### 2. 畢業流程(賽季收束 → 下屆開幕)

- 掛在 careerStage 收束(eliminated/champion)之後:
  **畢業儀式事件 → 名冊換血 → 新生入學 → 下屆開幕**
- 畢業儀式(events.js,儀式規格對標來投開箱):
  - 我方畢業者具名台詞(大山=隊長級離別重場;兩翼者=輕量但有記憶點)
  - 三年級**招募生**畢業走同流程(有專屬台詞:短暫相遇的告別)
  - 播報含對手 ace 畢業一句話+「舊王牌去向」伏筆(自由撰寫,埋大學章,不展開)
- 名冊換血=純函式轉換(比照 applyPoaching 模式,原 def 不可變)

### 3. 新生系統(混合制)

- 資料結構:手寫新生與程序生成補位員共用 member 結構,`origin: 'handwritten' | 'generated'`
- **第 2 屆手寫新生(MB,接班大山)**:人設稿由 Fable 產 2-3 個差異化方向
  (「前輩的影子」主題:仰慕型/叛逆型/毫無自覺型之類),名字用命名工程字族,
  **列入週末快照供 Sawmah 挑選**,本週先以佔位名接線
- 程序生成補位員:每屆 1-2 名,字族抽名(不與全域撞名——naming.test 擴充把關)、
  屬性種子決定論(同種子同新生)
- 新生入學事件:輕量見面演出(重場留給手寫新生的支線,本週不做支線內容)

### 4. 對手 ace 遞補 + 換人板凳(A1 搭車)

- 七隊 `reserves` 由各 2 名擴充至各 4 名(具名,字族命名,naming.test 涵蓋)
- **同一批 reserves 兩用**:
  a) 比賽中疲勞換人:對手體力低於閾值時換上 reserve(sim 決定論;弱隊 reserve
     能力差距明顯=板凳深度差異可感)
  b) 賽季末 ace 遞補:3 年級 ace 畢業 → reserves 中最強者升格新 ace
     (title 生成規則:沿用命名工程稱號風格)
- 兩者皆走 applyPoaching 同款純函式轉換路徑,**不另闢資料流**
- 對手換人 UI:沿用我方體力可讀性語言(標籤變色+迷你條已雙方對稱,換人時播報一句)

### 5. 測試(401 → 只增不減)

- 年級推進決定論、畢業名單正確性(功能核心不畢業)、招募生年級一致性
- 新生生成決定論(同種子同名同屬性)、全域不撞名
- ace 遞補鏈(畢業→升格→title)、對手換人觸發與決定論
- naming.test.mjs 擴充:reserves 擴充名單、新生字族、年級與名單一致
- 三屆快進整合測試:模擬連打三屆,名冊換血全鏈無錯、第 3 屆結束停在收束
  (生涯結算=W4,本週到收束即可)
