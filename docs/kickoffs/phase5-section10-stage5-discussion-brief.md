## 零、一句話

階段一～四已經把「機制」都補上了，階段五要做的是**把判定尺寸縮到真實排球的值**
（協議 6：三件套＋H 一批**一起校準，不得逐件收斂**）。

但有**四個問題在開始擰之前必須有答案**，否則收到一半才發現就會與其他旋鈕糾纏、分不出歸因
——那正是協議 6 存在的理由：

1. **接球／魚躍可及吃身高 ⇒ 自由人變成全隊最短。** 而 sim 裡「接球品質」早已定案為**技術主導**，
   理由正是「純到位做不出自由人」——同一個系統的兩個維度會philosophy相反。
2. **§4 留下的：`poor` 收斂後仍然是死的。** 攻擊池第三分支「勉強＝只剩兩翼高球」走不到。
3. **「分段收斂」沒有定義一段有多大、難度掉到多少要停手。**
4. **§5.3-bis 指定要在本階段重設的 `×1.5` 倍率門檻，需要新值或新形式。**

### 3.2 各動作可及半徑（現值 vs §5.2 目標值）

| 動作 | 現值 | §5.2 目標值 | 縮幅 |
|---|---|---|---|
| 接球 | **1.30**（定值，不分身高） | **身高 × 0.38** | 見 3.3 |
| 舉球 | 1.30（同上） | **0.45** | −65% |
| 扣球 | 1.30（同上） | **0.55** | −58% |
| 魚躍 | 1.30 × `DIVE_REACH_MUL` | **中位身高球員 ≈ 2.0 m** | 倍率須重導 |
| 攔網單人半寬 | **1.1** | **0.5**（全寬 1.0／雙人 1.55／三人 2.1） | −55% |

**現行程式的事實**：`reachRadiusFor(action, tuning)` 目前對四個動作回同一個 `REACH_RADIUS`
（魚躍另乘倍率）⇒ **現在完全不分身高、不分動作**。§5.2 是**新增**依賴，不是保留現狀。

### 3.3 身高 → 接球可及（§5.2 的 身高×0.38 之下）

| 角色 | 身高 | 接球可及 |
|---|---|---|
| **自由人（小白）** | 1.60 | **0.608** |
| 自由人（新生） | 1.70 | 0.646 |
| 舉球員 | 1.80 | 0.684 |
| 主攻 | 1.84 | 0.699 |
| 對角 | 1.87 | 0.711 |
| **中間手** | 1.92 | **0.730** |

⇒ **自由人比中間手短 0.122 m（20%），全隊最短。** 魚躍以可及為基底 ⇒ **等比縮，差距同步放大**。

### 3.4 能力值目前在哪些通道（決定「能不能補」）

| 通道 | 吃什麼 | 補得到可及半徑嗎 |
|---|---|---|
| `reachRadiusFor`（可及半徑） | 只吃 `REACH_RADIUS`／`DIVE_REACH_MUL` | **完全不吃能力值** |
| `receiveQualityMul`（接球品質） | `(control+reaction)/2` ＋ 到位程度 | 補**散佈品質**，不補半徑 |
| 自由人現有優勢 | 收縮指令讀對 ⇒ `timing = 1.0`（Perfect 窗） | 補**品質**，不補半徑 |
| §5 的補償條款 | 「只准走 AI 品質（提早判斷、起步更早、走位更準）」 | 補**到位**，補不了「球在 0.7 m 外構不到」 |

**球構不到就是構不到，能力值在這條路上沒有入口。**

### 3.5 這個問題 codebase 已經吵過一次，結論與 §5.2 相反

`src/sim/game.js` `receiveQualityMul` 上方的註解（原文）：

> 技術主導的理由：實測 AI 接球 dist≈1.1 不分角色（球進範圍就接），
> **純到位既無法讓自由人突出、又會全隊崩盤**

⇒ **接球品質早已定案為「技術主導」，正因為靠到位／身高那條路做不出自由人。**
§5.2 把「可及」推向身高主導 ⇒ 同一個系統兩個維度方向相反。

**而 repo 裡已經有一個「身高＋能力」的公式，只是沒接線**（sim 零呼叫，僅 `growth.js` 註解提及）：

```js
// src/sim/player.js —— 現況是死碼
export function defenseRange(p) {
  return p.height.current * 0.55 + (p.attributes.speed / 100) * 0.8;
}
```

⇒ 「可及 ＝ 身高項 ＋ 能力項」**不是新發明，是本專案自己寫過而未使用的形式**。
順手算：若 `身高×0.38 + (speed/100)×k`，要讓 speed 85 的自由人補回 speed 60 中間手的 0.122 m
⇒ **k ≈ 0.5**。而既有 `defenseRange` 的能力項係數是 **0.8**（補得更兇）⇒ 量級合理，不是硬湊。

### 3.6 `passTier` 現況與收斂後的反事實（§4 交付的接縫）

現況：**perfect 99.9% ／ poor 0.1%**（0.1% 是爆接 `blownTarget`，走另一條 `blownTarget` 不是散佈）。
d ＝ |一傳落點 − 二傳點| 的 p10 0.051／p50 **0.250**／p90 **0.450**／
**非爆接 max 0.547**（含爆接 max 6.871）。散佈上界 r ∈ [0.460, 0.562]，且 **d ＝ rand() × r**（均勻）。

門檻已相對化為 `係數 × 舉球可及半徑`，係數＝現值比例（1.2÷1.3 ＝ 0.923、3÷1.3 ＝ 2.308）：

| 舉球可及 | perfect 門檻 | poor 門檻 | perfect ／ ok ／ poor |
|---|---|---|---|
| 1.30（現值） | 1.200 | 3.000 | 99.9% ／ 0.0% ／ 0.1% |
| 0.80 | 0.738 | 1.846 | 99.9% ／ 0.0% ／ 0.1% |
| 0.60 | 0.554 | 1.385 | 99.9% ／ 0.0% ／ 0.1% |

⇒ `ok` 會從 0.0% 活到 **17.4%** ✅（§4.2 的要求成立）。

🔴 **但 `poor` 在任何舉球可及值下都是 0.1%**，而且這是**結構性的**，不是巧合：
`poor` 門檻 ＝ 2.308 × 可及，要碰得到 d 的非爆接上界 0.547 需要**可及 < 0.237**

⇒ **在 §5.2 的目標值下，攻擊池第三分支「勉強＝只剩兩翼高球」結構上走不到；

### 題 1｜接球／魚躍可及要不要含能力項？（自由人問題）

依據見 §3.3／3.4／3.5。三個候選：

| | 公式 | 後果 |
|---|---|---|
| **甲** | 純身高（§5.2 字面）：接球 ＝ 身高×0.38 | 自由人可及全隊最短（0.608 vs 0.730），魚躍等比縮。**AI 品質補不回來**（§3.4）。與 §3.5 的既有實測結論方向相反 |
| **乙** | 身高項 ＋ 能力項（比照既有 `defenseRange` 形式，能力項係數 k ≈ 0.5–0.8） | 快／技術好的自由人補得回來；形式有 repo 先例；**但 §5.2 的「身高×0.38」要改寫**，且要決定能力項吃哪個屬性（`speed`？`(control+reaction)/2`？） |
| **丙** | 純身高，但**明文接受**自由人可及最短，改由站位＋提早判斷承擔 | 不動 §5.2；風險＝§3.5 的實測結論說這條路做不出自由人 |

**若裁乙，請一併裁**：① 能力項吃哪個屬性 ② 係數量級（0.5／0.8／其他）
③ 魚躍倍率要不要跟著改成「身高＋能力」的基底。

### 題 2｜`poor` 收斂後仍是死的，本階段處置嗎？

依據見 §3.6。**在 §5.2 的目標可及 0.45 下 `poor` 門檻 1.038，而 d 的非爆接上界只有 0.547
⇒ 結構上碰不到；要靠縮可及來讓它活，可及得低於 0.237（連 0.25 都不夠）。** 三個候選：

| | 作法 | 後果 |
|---|---|---|
| **甲** | 調 `poor` 的相對係數（現 3÷1.3 ＝ 2.308 → 例如 1.0） | 可及 0.45 時 `poor` 門檻降到 0.45 ⇒ 第三分支活過來（依上表 d ≥ 0.45 約佔 10%）。**係數在 §5.3 白名單上**（`passTier` 相對門檻分位數）⇒ 合法，且是**唯一**有效的旋鈕 |
| **乙** | 不動係數，靠**放大散佈**讓 d 長大到能碰 1.038 | ⚠ `SCATTER_MAX` 在 §5.3 **明文凍結** ⇒ 此路須先解除凍結，不建議 |
| **丙** | 接受第三分支是死的，登記進 §十 病表（與十-4 同型：機制存在但輸入是死的） | 不動任何旋鈕；但那是本卷第五件同型病 |
