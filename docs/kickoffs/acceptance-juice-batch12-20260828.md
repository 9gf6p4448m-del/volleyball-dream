## 驗收條件（逐條、可機械判定）

- **A1 取樣優先、合成 fallback**：
  a) 取樣載入成功時，擊球（重扣）事件播放的是取樣 buffer（測試：stub decode 成功
  → 斷言走 sample 路徑）；
  b) 取樣載入失敗（fetch 拒絕／decode 丟錯／檔案不存在）時，同一事件流仍發出
  現狀合成音（斷言走 synth 路徑），**無未接 rejection、無 fatal 簾幕**。
  紅燈定義：把載入器改成必失敗，a) 應紅；把 fallback 拔掉，b) 應紅。
- **A2 音訊失敗永不致死**：既有 audio 死屏 E2E 維持綠；新增「音檔載入失敗」情境的
  同型測試（模擬 fetch 全滅→遊戲照跑、無 fatal）。
- **A3 關鍵分聲浪動態**：局點/賽點的發球準備相位 crowd level 壓低（屏息），該分結束
  （DEAD_BALL）後聲浪高於常態（爆炸）。斷言＝setCrowdLevel／等效 gain 目標值的序列：
  屏息值 < 常態值 < 爆炸值，且只在局點/賽點觸發（非關鍵分不觸發屏息）。
- **A4 BGM**：
  a) 主選單顯示期間有主題曲播放路徑被啟動（autoplay 政策下允許「首次手勢後開始」）；
  b) 比賽中氛圍層音量/強度是「緊張度」的函數（輸入＝分差與局點/賽點旗標；斷言＝
  緊張度高低兩組輸入產生的目標音量不同且方向正確）；
  c) BGM 檔案路徑集中在單一清單（換檔即生效：替換 `public/audio/bgm/` 同名檔即可，
  不需改程式）；
  d) 音量設定（至少：總開關/靜音鈕＋音量滑桿）存 localStorage，重整後生效。
- **A5 體積與快取**：
  a) 新增進 precache 的音檔總體積 ≤10MB（機械：實測 dist 內音檔加總）；
  b) BGM 檔**不進** SW precache manifest（機械：build 後檢查 manifest 不含
  `audio/bgm/`），以 streaming/lazy 方式載入。
- **A6 授權**：每個進 repo 的音檔在 `public/audio/ATTRIBUTION.md` 有來源＋授權
  （CC0 或 CC-BY 標注）；查無授權的素材不進 repo。
- **A7 sim 零改動**：`git diff src/sim/` 零檔案；sim-hash 逐值不變（照卷慣例當閘）。
- **A8 測試全綠**：既有全套（2295）＋本批新增，一條不紅。
- **A9（使用者試玩項，非機械）**：Sawmah 真機（iOS PWA）：①聽感方向 OK ②切出
  LINE/鎖屏再回來聲音還在（ensure 重試防線）③BGM 曲風聽 demo 後定案。試玩即改，
  不受凍結約束（音量數值/曲目/混音比全屬提案值）。
