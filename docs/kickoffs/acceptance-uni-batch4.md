## ★ 範圍更正（動手前發現，據實記載）★

卷宗原文寫「**解除**三屆封頂」。查證後**不能那樣做**：

1. `careerStore.js:165` 的 `if (season.index >= 3) return false` 一拿掉，玩家就能推進到
   第 4 屆——但**大學賽程是批 6**，推進過去會掉進一個沒有賽程的空狀態。
   ★ 不開一扇通往還不存在的房間的門 ★
2. `careerState.js:363` 的 `currentGrade` 查證後是給**對手 ace 三年級畢業**用的
   （`:380`／`:409`），而大學有自己的對手池 ⇒ **它未必要動**，本批不動它，
   避免為了「章節化」去改一個其實只服務高中對手的函式。

**本批改做**：把「屆數」的語意章節化——引入「**章內第幾年**」與「**各章的年限**」，
封頂判斷改由章節決定。高中的行為**逐值不變**（仍然三屆封頂），大學的門先留著、
由年限決定何時開，等批 6 有賽程了再讓它真的走得過去。

## 這一批要交付什麼

1. `chapterSeasonOf`：全域 `season.index` → **章內第幾年**（高中＝原值；大學＝進入後起算）。
2. `seasonCapOf`：各章的年限（高中 3；大學階段一 1）。
3. `careerStore` 的封頂判斷改吃上面兩支，**不再寫死 3**。

**本批不做**：大學賽程、對手池、升學畫面、`currentGrade` 的改動。

## 驗收條件

- **B4-1 高中行為逐值不變**★最重要★：高中章的封頂結果與本批實作前**完全相同**
  （第 1／2 屆推得動、第 3 屆推不動）。
  ▸ 反向對照：把年限改成 4，第 3 屆就推得動 ⇒ 證明這條驗的是真的判斷式，不是恆假。
- **B4-2 章內年份換算正確**：大學章第 N 年 = `season.index - enteredAtSeason + 1`；
  高中章恆等於 `season.index`。
  ▸ 反向對照：進入賽季不同的兩份存檔，同一個 `season.index` 要算出**不同**的章內年份。
- **B4-3 大學年限存在且可調**：階段一＝1 年（打完一年就到頂），值集中在一處，
  不得散落。
- **B4-4 舊存檔零遷移**：沒有章節欄位的存檔一律當高中，封頂行為與實作前相同。
- **B4-5 零外溢**：`npm test` 全綠；`sim-hash` 逐值＝基準。

## 鑑別力要求

B4-1 的反向對照是這一批的核心——「高中還是三屆封頂」很容易寫出一個**恆假**的判斷式
（例如永遠 return false）而全綠。必須證明**改了年限就會改變結果**。
