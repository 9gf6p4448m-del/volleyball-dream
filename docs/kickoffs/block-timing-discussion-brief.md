## 一、一句話

**這個遊戲的「攔網」有三分之一不是攔網，而是落地後站著擦到球；而且牆從來不去兩翼。**

## 二、五個實測發現（全部真實路徑，樣本與 SE 已附）

### 1. 攔網有一大塊來自「已落地的攔網手」

| 守方 | 攔網接觸中「已落地」的比例 |
|---|---|
| **commit 人格（曜石）** | **79.43 ± 0.76%** |
| **read 人格** | **2.49 ± 0.25%** |

機制：`blockUntil` 每 tick 被 block intent 續期（`game.js:479`），
而 `blockPlanAirborne` 的窗是 `TUNING.BLOCK_WINDOW`（48）⇒ **有效牆上資格最長到起跳後約 95 tick**，
遠超 `AIR_TICKS`（24）；落地後 `blockTopEdge` 回站立摸高（`player.js:131`），仍搆得到貼手頂的低平球。

**它幾乎完全等於 commit 人格的 `press` 手態**（`press` 桶 98.08% 發生在落地後，
且 `press` 只有 commit 產得出來——`ai.js:1372` `hand = commit ? 'press' : …`，read 側 n=0）。

### 2. 關掉它，攔網不會形同關閉——但 commit 牆會

反事實（讓攔網資格在 `AIR_TICKS` 用完就結束）：

| 桶 | 前 → 後 |
|---|---|
| body 手身攔回 | 2,858 → 2,948（**不動**） |
| graze 擦頂 | 747 → 758（**不動**） |
| graze 擦側 | 1,003 → 1,001（**不動**） |
| **press 壓球** | **2,186 → 45（−97.9%）** |

| 守方 | 觸手率 Δ | 被攔死率 Δ | 攻方得分率 Δ |
|---|---|---|---|
| **commit 牆** | −9.57 ± 0.25 | −4.12 ± 0.15 | **+3.95 ± 0.47** |
| **read 牆** | −0.19 ± 0.34 **分不出** | +0.12 ± 0.15 **分不出** | −0.73 ± 0.45 **分不出** |

⇒ **read 牆完全不依賴這個機制；commit 牆有 77% 的觸手、89% 的攔死靠它撐著。**

### 3. ★ 玩家手動攔網不受影響——但只有其中一種修法 ★

| 修法 | 玩家手動攔網 |
|---|---|
| **拿掉 `blockUntil` 續期** | **100% 不受影響** |
| **把牆上資格綁物理滯空** | **會被砍掉** |

原因：玩家的攔網**本來就不續期**（`matchControls.js:390` 一次投遞就 `queuedAction = null`），
而且玩家在 sim 裡**根本沒有攔網滯空狀態**——他那個 48-tick 窗是**與身體無關的計時器**。

⚠ 反事實臂只動了 `tryBlock` 的資格閘，**沒動 `blockUntil` 續期本身**
（改續期會讓判定窗過期後當場重開新窗＝原地重跳，那是另一種行為）。

### 4. 牆只守中路，兩翼是空的

| 型態 | 過網 \|x\| p50 | 牆首手 x p50 | 接觸中已落地 | 被攔死率 |
|---|---|---|---|---|
| **內切 left_inside** | 0.502 | 0.000 | **54.4%**（對 commit **84.0%**） | **13.3%** 全樣本最高 |
| 快攻 | 0.482 | 0.000 | 61.0%（80.0%） | 5.6% |
| 交叉 | 0.779 | 0.000 | 36.8% | 5.2% |
| **右翼 right** | **1.906** | **0.000** | **0.5%** | **0.00%（n=3362）** |

**牆首手 x 的 p50 恆為 0.000。** 過網點靠中間的型態全部暴露，兩翼直線根本碰不到。
（對照：read 牆**會瞄**——左翼牆首手 1.980 對上過網 1.435、帶內 73.6%。**兩翼的洞是 commit 專屬的**。）

### 5. 三人牆補不了兩翼（已驗，不要再試）

恢復 close 預算判斷（「趕得上就併」）的反事實：

- 三人牆回到 **47.9%**，且**確實主要併在兩翼**（左翼佔該型 59.7%、右翼 57.5%）——**前半成立**
- 但**牆覆蓋寬只從 1.550 → 2.100m（＋0.55＝剛好一格），牆心幾乎沒動**（−0.275 → −0.237）
- 球從 |x|≈1.9 過網 ⇒ **缺口 1.4m，補 0.55m 補不到**：帶內 0.3% → 2.5%、右翼被攔死率 **0.0% → 0.0%**
- 臂間配對 Δ：**攔網三個指標全部分不出**；救起率 **−5.13 ± 0.97**、攻方得分率 **+4.76 ± 1.00**（都變差）
- 吊球退步：「牆上跳過的人自己撿」21.2% → 30.0%

⇒ **瓶頸是牆瞄不準 1.4–1.9m，不是人數。** 先修瞄準，三人牆才有意義。

## 三、要裁的題

### 題 1：修「落地後還在牆上」嗎？怎麼修？

| 選項 | 效果 | 代價 |
|---|---|---|
| **拿掉 `blockUntil` 續期** | commit 牆掉 77% 觸手／89% 攔死；玩家手動攔網 **不受影響** | commit 人格幾乎被拆掉一半戰力 ⇒ 難度大位移、要重跑熔斷 |
| **綁物理滯空** | 同上，但**玩家手動攔網也被砍** | 玩家會覺得攔網變弱 |
| **不修** | — | 「攔網」有三分之一是站著擦到的；夾塞永遠開不回來 |

⚠ **款 3 警報器餘裕只剩 1.3pp**（gap 6.3、門檻 5）——任何壓縮 commit 離地率的改動都可能直接打翻它。

### 題 2：牆要不要去兩翼？

現在 `blockAimX` 對 commit 走 `blockCommitRead`（猜助跑），而它只認 `lz ≤ DEPTH_LZ(2.9)` 的候選；
**兩翼助跑起點 lz 3.58 在偵測範圍外**。這是同一個洞的兩個面：
- 攔網端：牆看不到兩翼的人 ⇒ 不去
- 攻擊端（段 F）：**玩家當 OH 時「助跑帶走攔中」發生率 0.0%**（結構性恆假），當 MB 時 64.2%

放寬 `DEPTH_LZ` 的反事實：`jtDiff` 1.8→8.1%、`xDiff` 0.5→6.0%（分歧大幅上升），
但**交叉反而被完全看穿**（交叉 `jtDiff` 掉到 0.0%、對方得分率 51.7→67.5%）。

⇒ 「讓牆看得更遠」與「交叉還有沒有用」是**直接衝突**的。這是憲法 §零（read／commit 賭局的定義）。

### 題 3：commit 的起跳訊號要不要重做？

實測：**commit 的起跳 p50 ＝ set+1，46–83% 的球走「位準」分支**
（二傳觸球那一刻條件就已成立、當場拔起），下降沿只佔少數。
「該吃第幾個下降沿」這個問題**對多數球不適用**。

第一個沿指到真攻擊手：快攻 15.1%／兩翼三速 34.8%／兩翼二速 20.3%／**後排 0.0%（0/227，結構性）**。
最後一個沿更差（22.0%），且**結構上不可即時判定**。

### 題 4：段 F 回饋層的三選一

裁定書 §六.4 要兩項回饋（玩家助跑帶走攔中／假動作騙到 commit），實測後**停手**：

- **① 玩家當 OH 時發生率 0.0%**（結構性恆假，見題 2）；當 MB 時 64.2% 但**誤歸因率 38.2%**
- **② 假動作騙到 commit**：發生率 30.1%，但 **47.3% 是 commit 盲賭中路**（沒鎖任何人）
  ——「攔網手黏在誘餌身上」與「他誰也沒讀到、只是賭中路」在**可觀察量上完全同形**

停手門檻：發生率 ≥5%、誤歸因率 ≤20%（回饋每 5 次錯 1 次以上，玩家學到的因果就是錯的）。

| 選項 | 內容 |
|---|---|
| **改判準** | ② 改用無歸因版（「他賭了、賭錯了，空門！」不宣稱誰把他帶走）——發生率 53.0%、**誤判率 0**。但那不是裁定書要的歸因 |
| **改機制** | 放寬 `DEPTH_LZ`／延後 commit 決策窗 ⇒ ① 對 OH 玩家才可能發生。動 sim、要重跑熔斷，且與題 2 衝突 |
| **留下一卷** | 等本卷落地後再做 |

★ **設計提示**：**MB 玩家有 64.2% 的球真的把牆帶走了，但遊戲從來沒告訴他。**
這正好是 MB 在組合攻擊裡的位置（永遠是誘餌），也是集訓卷「默契依位置加成」的 MB 那一格。
