## §1 階段一：機制落地在等價值（行為零變化，hash 逐值證明）

**本階段結束時 `npm test` 綠且 sim 行為與 `fa7e3f4` 逐值相同。** 做法同 W1 §9 `ActionPhaseContract`。

### 1.1 3D 可及球體（取代閾值堆）

```
觸球成立 ⟺ |球心 − 手點| ≤ 該動作可及半徑 + BALL.RADIUS
手點由動作相位決定（起跳中的手點隨跳躍曲線上移）
```

**等價實例化**：可及半徑填 1.3、舉球手點以退化形式重現 `touchCeiling = standingReach + 0.35`
（`ai.js:1083`）、接球維持水平判定行為。**hash 逐值證明行為零變化。**

同時修掉 ⑤ 的不一致：`game.js:454-455` 純球心對球心不吃 `BALL.RADIUS`，
而攔網高度判定有吃（`b.y > blockReach(...) + BALL.RADIUS`）——**統一為都吃**。
（此項會改變行為，允許在本階段記為第一筆數值差異並單獨 hash 標註。）

### 1.2 攔網帶模型（結構，數值仍等價）

三層分工：

| 層 | 職責 |
|---|---|
| **幾何閘門** | 帶＝各攔網手區間的**聯集**，判斷球的過網 x 是否落在帶內 |
| **邊緣區** | 落在帶的邊緣 ⇒ 擦手（取代 `BLOCK_GRAZE_CHANCE 0.22`） |
| **屬性擲骰** | 只決定**碰到之後的結果分佈**：攔死／打手出界／軟攔彈回可 dig／被 tool |

高度＝矩形：頂邊為各人自己的 `blockReach + BALL.RADIUS`。

**等價實例化**：單人半寬填 1.1、結算仍取 dx 最小者的 `block` 屬性、邊緣區寬度反解成 0.22 的等效值。
**hash 逐值證明行為零變化。**

> **屬性語意改變是本卷的核心**：屬性不再決定「有沒有攔到」（那交給幾何），
> 只決定「攔到之後發生什麼」。真實排球中完整雙人牆對上好攻擊手照樣被得分，用的就是這條。
> 這樣多人加成**完全由幾何湧現**（協議 7），而屬性不貶值。

## §2 階段二：攔網三段狀態機（無法等價，這是真的行為改變）

### 2.1 現況（必讀，這是本節要改掉的東西）

`ai.js:820`：`let nx = clampCourtX(game.ball.x + laneOff);`
——攔網手目標 x **逐 tick 直接吃球的 x**，不吃攻擊手、不吃 `spikeAimsFor` 的過網點，
無加速度、無慣性。球最後會飛到攻擊手手上 ⇒ **用未來答案本身當導航**。

而 `reactionTicks`（`ai.js:1137`）在攔網分支（`ai.js:793-848`）**完全沒被呼叫**。

### 2.2 三段狀態機

| 段 | 目標 x |
|---|---|
| **讀** | 陣型基準位（**只吃 `laneOff`**，不再吃 `ball.x`） |
| **判** | **二傳觸球** ＋ 反應延遲後選定一名攻擊手；目標 x 由**該攻擊手的預測過網點**導出 |
| **關／踩定** | 移動至該 x，時機到起跳 |

### 2.3 read 與 commit 共用同一條路

「判」的程式**已經存在**——`blockCommitRead()`（結構上拿不到二傳選了誰、有
`B1-SCAN-BEGIN/END` 靜態掃描守著）＋ `blockCommitTargetX()`（有 close 預算），
只是整段掛在已停派的 commit 分支下，read 分支完全繞過。

**兩種人格共用同兩支函式，只有觸發 tick 不同**：

| 人格 | 決策時點 |
|---|---|
| read | 二傳觸球 ＋ 反應延遲 |
| commit | 二傳觸球**之前**（辨識到助跑就動） |

### 2.4 五個硬性規格

| # | 規格 |
|---|---|
| a | 讀期目標 x **不得吃 `ball.x`** |
| b | 起算事件＝**二傳觸球**（不是攻擊手起跳——快攻在二傳觸球前已離地，W1 實測 100%） |
| c | 延遲**沿用** `max(6, 24 − reaction×0.16)`，**不得另立常數** |
| d | **AI 不得額外加罰**。玩家的 48 tick 寬窗是既有的手機友善拍板，再給 AI 隱形手銬＝違反協議 3 |
| e | **不做加速度／慣性模型**（移動不是瓶頸：窗長 1.333s × 移速 2.8–5.2 m/s ＝ 可跑 3.7–6.9m，而實測最大淨位移僅 4.864m）。改做**改判須重新踩定**的 tick 代價；**已起跳者不得改判** |

> **e 同時交付 §十二 假扣真傳（真版）的依賴**——攔網手要真的被騙起跳、落地、來不及再跳。

### 2.5 明令不做

**不得讓攔網手讀「二傳朝向」。** `blockCommitRead` 的簽章與靜態掃描測試不得放寬。
二傳觸球在本案中是**「何時允許做決定」的閘門，不是「決定時看到什麼」的資訊來源**。
（朝向線索＋背舉是成對的上層玩法，已推出本卷。）

#### 2.6-b 新指標：拆成三個數，不要合成一個百分比

量測時點：**球心通過網面那一 tick**（含插值）。

| 代號 | 定義 | 誰會動它 |
|---|---|---|
| **H** | 球的過網 x 落在**該 MB 自己**的帶內 | 帶寬（階段五）、關牆行為（階段三） |
| **V** | 球心 y ≤ 該 MB **當下**頂邊（`blockReach + BALL.RADIUS`） | **timing 幾何化（階段二）** |
| **G** | H ∧ V | 驗收用 |

**E 表判 G；H／V 分開報作為診斷。** 幾何化只動垂直、帶寬縮只動水平，
合成一個數，階段五之後分不出下降來自哪一邊。

四個釘死的定義細節，不得自行解讀：

1. **時點＝球心通過網面那一 tick。** 不得用「窗內任一 tick 曾涵蓋」——手曾舉起但球到時已放下，
   **那就是沒攔到**。此選擇與既有機具一致（`netCrossingX`、§3.3 頂邊、縫寬定義皆定義在過網面上）。
2. **算幾何閘門，不算攔網事件。** 屬性擲骰參數在階段五白名單上，用事件率當驗收＝讓階段五旋鈕
   污染階段二的行為驗收。**G 必須是純幾何。**
3. **帶與頂邊都取「該 MB 自己的」，不是全隊聯集。** 隊友補位蓋住球會把 MB 的失敗洗掉。
4. **球半徑約定沿用 §3.3**：球心 y vs `blockReach + BALL.RADIUS`（⟺ 球底 vs `blockReach`）。

② **協議 1 要求「以真實排球的手臂可及範圍定出各動作的合理觸球幾何（水平＋垂直分開定），
