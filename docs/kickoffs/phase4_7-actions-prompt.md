# W8 實作交付 — 扣球動作重製（相位驅動骨架）

> 對象：Claude Code
> 專案：排球夢（Three.js + Vite + PWA）
> 前置：W7 已結案（體能／氣勢／板凳／宿敵情緒系統）
> 本文件為自包含交付規格。**若本文件以附件形式提供，請先完整展開附件內容再開工，不要只讀摘要。**

---

## 0. 一句話目標

把扣球從「起跳後人在空中往前飄」改成「助跑動量被制動吃掉、原地拔起、空中弓身、鞭打擊球」的真實排球動作，做法是導入 **sim 時間錨點 → 表現層相位映射** 的動畫架構，並補上三個關鍵關節。

**本輪只做扣球。** 攔網／舉球／接發不在範圍內——它們在 W9+ 沿用本輪建立的同一套框架。

---

## 1. 問題根因（先確認理解再動手）

現況症狀：起跳後角色沿助跑方向持續前移，看起來像「往前跳」而非「往上拔」。

根因**不是**關節數不足，是兩件事：

1. **缺少制動轉換（braking step）**：真實扣球最後兩步是煞車動作——腳跟先觸地、重心後壓、膝踝離心收縮，把助跑的水平動量轉成垂直動量。現行實作把助跑水平速度直接帶進飛行階段，所以前飄過大。真人扣球的空中水平位移只有約 **0.3–0.5 m**。
2. **位移驅動動作，而非動作驅動位移**：現行是先算出角色座標、動畫再貼上去，導致腳掌在地面滑動、動作與移動脫節。正確方向是根運動（root motion）由動作相位決定。

**驗收時我會回頭確認這兩點是否真的被處理，而不是靠調參把前飄數值壓小。**

## 3. 相位契約（本輪的核心交付）

### 3.1 sim 端提供的時間錨點

sim 在扣球事件成立時產出一個唯讀結構（欄位名可依現有慣例調整，但語意必須齊備）：

```
SpikeTimeline {
  playerId
  approachStartTick   // 助跑起始
  brakeStartTick      // 制動步開始（雙腳併攏前的最後一步觸地）
  takeoffTick         // 離地
  contactTick         // 觸球（sim 既有事件，不新增判定）
  landTick            // 落地觸地
  recoverEndTick      // 緩衝結束、回到可行動姿勢
  approachDir         // 助跑方向單位向量（水平）
  apexY               // 最高點（由既有跳躍能力計算，不新增參數）
  handedness          // 慣用手，預設右
}
```

**這些欄位必須全部由既有 sim 邏輯推導，不得為了動畫新增任何影響判定的參數。** 若某個 tick 目前 sim 沒有明確定義（例如 `brakeStartTick`），用既有數值反推（例如自 `takeoffTick` 回推固定 12 tick），並在程式碼註解寫明推導方式。

### 3.2 表現層相位映射

表現層把 tick 錨點映射成 0–1 正規化相位，**每個相位獨立正規化**（不是整段一條 0–1）：

| 相位 | 區間 | 典型時長（60Hz） | 語意 |
|---|---|---|---|
| P0 助跑 | approachStart → brakeStart | 可變 30–40 tick | 步頻循環、雙臂後擺蓄勢 |
| P1 制動起跳 | brakeStart → takeoff | 12 tick (0.20s) | 腳跟先觸、重心後壓、雙臂由後向前上甩 |
| P2 上升弓身 | takeoff → contact−4 | 20 tick (0.33s) | 弓身、髖肩分離、非慣用手上舉指球 |
| P3 鞭打擊球 | contact−4 → contact+3 | 7 tick (0.12s) | 肩→肘→腕依序解鎖 |
| P4 下降收臂 | contact+3 → land | 14 tick (0.23s) | 手臂跨體收回、身體伸展回中性 |
| P5 落地緩衝 | land → recoverEnd | 15 tick (0.25s) | 屈膝吸收、重心下沉再回升 |

**時長為設計基準，實際由 sim 錨點決定；相位速度隨錨點間距縮放，不得硬寫播放秒數。** 這是「相位驅動而非定長播放」的具體要求：助跑短則相位跑快，動作不截斷。

## 4. 骨架擴充（只加三個，不要多加）

現行幾何關節角色需補：

1. **脊椎分段** — 至少 `spine_lower`（腰）＋ `spine_upper`（胸）兩節。沒有這兩節做不出弓身→收腹的輪廓，那是扣球最有辨識度的剪影。
2. **手腕** — `wrist_dominant`。觸球瞬間的壓腕 snap 是排球辨識度最高的一幀。
3. **骨盆獨立於軀幹** — `pelvis` 可獨立於 `spine_lower` 旋轉，用來做髖肩分離。

**明確不要新增**：手指、鎖骨、頸部細分、腳趾。投報率過低。

新關節必須：
- 沿用既有自訂關節軸慣例
- 不新增 draw call（合併進既有 instanced 批次）
- 對既有的走位／接球／攔網姿勢維持中性預設值，**不得改變其他動作的既有外觀**

## 5. 動作規格（右手選手；左手鏡像）

### P0 助跑
三步節奏（左–右–左）。雙臂在最後一步前擺至身後約 30–40°。軀幹前傾 15–20°。腳步落點沿 `approachDir`，最後一步步幅明顯放大。

### P1 制動起跳 ★ 本輪成敗關鍵
- **腳跟先觸地**（heel-plant），不是腳掌平踩
- 重心相對雙腳落點**後移**，膝關節屈曲至最深（約 90–110°）
- 軀幹前傾角度在此相位內由 20° 快速回正至 5°
- 雙臂自身後向前上方全力甩起，甩臂在 `takeoff` 前 2–3 tick 到達最高
- **水平速度在此相位內衰減至 15% 以下**——這是把前飄壓進 0.3–0.5 m 的機制，不是靠事後夾限

### P2 上升弓身
- 脊椎進入反弓：`spine_upper` 後仰，`spine_lower` 跟隨較少
- **髖肩分離**：`pelvis` 先向擊球方向旋轉，`spine_upper` 延遲 3–4 tick 跟上
- 慣用手手肘高過肩，前臂後倒；非慣用手上舉指向球（真人的瞄準與平衡動作，缺了會很假）
- 雙腿自然屈膝，小腿後收

### P3 鞭打擊球
嚴格依序解鎖，**不得同幀一起轉**：
1. 肩（contact−4 → −2）
2. 肘伸展（contact−2 → 0）
3. 腕壓（contact → contact+2）

同時：`spine_upper` 由反弓快速收腹前屈，`pelvis` 完成轉體。這條鏈是「像真人」的全部來源。

### P4 下降收臂
擊球臂沿對角**跨體收回**（右手收向左髖），不是原路縮回。身體由前屈回到中性。

### P5 落地緩衝
雙腳觸地屈膝吸收（膝角回到 100° 左右），重心下沉約 0.15 m 再回升。**落地不得瞬間回到站姿**——這是目前所有動作最廉價的破綻。

## 6. 程序式疊加層（在基礎姿勢之上加算）

1. **腳部 IK 鎖地** — 支撐腳在接觸地面期間，腳掌世界座標**固定不動**。這一項的觀感提升大於整個骨架擴充，優先實作。
2. **慣性延遲** — 末端關節（手、前臂）相對軀幹延遲 2–3 tick 跟隨。用固定延遲緩衝，不得用隨機。
3. **重心傾斜** — 依當前水平速度給軀幹側傾／前傾偏移。
4. **視線 look-at** — 頭部朝向目標。**注意：視線欺敵是既有 sim 機制，本輪頭部朝向必須讀取 sim 既有的視線值，不得另外自算，否則會與假動作系統打架。**

疊加層全部為純函式、無狀態外部依賴（除既有 sim 狀態），確保 replay 可重演。
