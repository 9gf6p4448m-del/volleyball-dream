## 先講一件做不到的事（`02 §6.1` 條 4）

**「每 tick 避讓造成的位移」無法從 `stepGame` 外面直接量到**：
`src/sim/game.js:319-320` 的 `px/pz` 快照取在 `applyMove` **之前**，而 `separateTeammates`
（`game.js:333`）是本 tick 最後一個動 actor 的東西 ⇒ 「applyMove 之後、避讓之前」那一格座標
沒有對外出口。也無法做「關掉避讓」的 A/B 軌跡差：`SEP_RADIUS`／`SEP_PUSH` 是 module-level
`const`（`game.js:426-428`），不是 `TUNING`／`AI` 那種可 patch 的物件，關掉就得改 `src`（禁區）。

因此本節給兩個量，**都不是代理指標**：
- **(i) 推導**：把 `game.js:445-452` 的算式對觀測到的 `d` 反解。未觸頂支下推完距離
  `d = hypot(0.55, 1.2×push)` ⇒ `push = sqrt(d² − 0.55²)/1.2`，單人位移 `= push × hypot(1, 0.6)`。
  觸頂支（`push = 0.08`，需 `d_pre < 0.39`）在本批從未發生（`d < 0.55` 的 tick 數 = 0）。
- **(ii) 直接**：該 tick 兩人的**實際**總位移（連續兩次 post-step 座標差）。它是 (i) 的**上界**
  （實際位移 ＝ 自己要走的 ＋ 避讓推的），也是「玩家眼睛看得到多少移動」的上界。

**(i) 的已知偏誤（誠實標註）**：判定「這 tick 觸發過」用的是 `d ≤ 0.5583`，但沒觸發而自然
落在 `[0.55, 0.5583]` 這 8.3mm 帶裡的 tick 也會被算進去。上界估計＝拿隔壁帶的密度外推：
觸發帶 3103 tick / 8.3mm ＝ 374 tick/mm，隔壁帶（0.5583–0.71，152mm）2394 tick ＝ 15.8 tick/mm
⇒ 觸發帶比隔壁密 **24 倍**，混入的隨機路過約 `15.8 × 8.3 ≈ 131` tick ＝ **約 4%**。(i) 因此高估 ≤4%。

- **解析力**：完成率的 SE ＝ 2.1pp ⇒ 小於約 4pp 的真實差異本組樣本分辨不出來，
  只能說「沒有 ≥4pp 的損害」，不能說「一定零損害」。前三項是 p50 逐值相同，解析力不成問題。

## 結論

**純視覺，可不修。** 支撐它的數字是 **`startTick` 到位距離兩組 p50 皆 0.0000m**
（被推開的球一樣準時站上助跑起點）＋ **完成率差 −2.3pp 落在 1.1 SE 內**（無法與 0 區分）；
`takeoffTick` 與擊球點兩項也都沒有往壞的方向動（擊球點甚至近 8cm）。
唯一真實的差是視覺量級：累計側移 p50 0.181m → 0.415m。要不要為這 0.23m 動走位路由層，
是品味／優先序判斷，屬 Sawmah 的決定，不是 bug 修復。
