## 2. 工程事實（會議評估工作量用）

1. **資料底已落**：`save.career.finalRally = { matchId, seasonIndex, snapshot, steps }`
   ——冠軍點那一球的「發球前 sim 整包快照＋整球 Intent 流」；VCR 錄製規格＝
   快照＋同序 Intent 重演＝**逐格一致**（賽中回放同一契約，決定論背書）。
2. **賽中回放引擎已存在**：matchLoop 的 `s.replay`（死球後回看最後 3 秒、半速）與
   情蒐錄影帶（tape）共用同一條「快照＋Intent 重演」管線——**在主賽場舞台上**跑。
   4.6 缺的是把這套搬進 careerScreen（DOM 層、無主賽場）。
3. **DOM 內嵌 three 舞台已證可通**：`ritualStage.js`（單人聚光）與 4.5B `beatStage.js`
   （多人劇情小舞台）兩個前例——獨立 renderer/canvas、WebGL 失敗退化、dispose 慣例齊全。
   但兩者都是「幾個人的小場景」；**全場重演＝球場＋網＋十二人＋球＋燈光**，
   量級接近主賽場（`arena/court/players/geoAnimator/ballView` 模組理論上可重用，
   重用範圍＝本輪最大工程判斷）。
4. **鏡頭資產**：cameraRig 模式制＋4.5B 四鏡位模板（beatShot 純函式：confront 對峙／
   exit 離場／rimlight-solo 單人邊光／stands 看台遠景）＋招牌演出「sig」三構圖
   （4.5B 三道招牌演出的鏡位——OH 隔網看被騙攔網手／MB 網帶上方俯視／OPP 低機位
   看擊掌，即「決定性一拍的特寫鏡位」）——重演導播可組裝的鏡位語彙已有一批；
   把它們串成「一顆球從發到落的鏡頭腳本」＝本輪新東西。
5. **演出時鐘**（4.5B §2-2）：牆鐘 rAF、跳過＝播完逐值一致——重演的播放/暫停/
   跳過直接吃這套。
6. 真機基準：60 FPS 硬底線沿用；4.5 關卷時留有懸案（Sawmah 試玩截圖曾見 35FPS，
   但當時**沒記下是哪個場景**——移入 4.5B 快照的滾動試玩清單追蹤，尚未定位病灶）
   ——**全場重演舞台是新的效能大戶，本輪必須自帶 FPS 預算**（見 §3 題2 的降規把手）。

## 3. 待拍板題（會議主軸）

1. **回放範圍**：A＝只做冠軍點（finalRally 現有資料，最小可交付）；
   B＝A＋宿敵之戰收藏（資料側要開始「多錄哪些球」——錄製時機與容量規則要一併拍：
   逐屆天鷹掛點場的關鍵球？勝負點？）；C＝典藏館（任意場次關鍵球，錄製規則更大）。
   實作端傾向 B：A 的引擎蓋好後，B 只是資料錄製面的擴充；C 滾 Phase 5+。
2. **舞台規格**：全編制重演（12 人＋完整場館）vs 焦點重演（六人半場/僅關鍵球員＋
   簡化背景）——60 FPS 與記憶體代價 vs「冠軍點就該全景」的儀式感。
   實作端傾向：重用主賽場模組做全編制、但場館用常規館幾何（不搬冠軍館穹頂）。
   **注意這與 §2-6「重演是效能大戶」的張力**——調和手段＝FPS 未達標時逐項降規，
   且**降規只走 URL 參數、不自我降級特效**（架構鐵律，即「Phase 0 精神」：Phase 0
   真機驗收時定的規矩——降規檔位由使用者手動掛參數，程式不偷偷關特效）。
   降規序沿 4.5B 慣例：觀眾 attendance → 上層看台 → 陰影 → 演出短版化。
   **實作端不預設方案，先做全編制原型量真機 FPS，數據回來再定降規檔位**——
   本題會上先拍「儀式感目標」（要不要全景），FPS 落點試玩定。
3. **鏡頭導播**：重演時鏡頭誰來運——A＝固定廣角＋既有慢動作；B＝自動導播
   （跟球＋關鍵拍切 sig 語彙鏡位＋落點特寫收尾）；C＝玩家可切視角。
   實作端傾向 B（語彙現成），C 滾後。
4. **入口與時機**：重演在哪裡被看到。現況＝生涯結算流程（三屆定格→生涯數據→
   招募全記錄→**關鍵球典藏行**→謝幕→送別→畢業儀式→「第一章・完」）裡，
   「關鍵球典藏」目前只是一行**靜態文字**（「🎬 關鍵球典藏：第 N 屆冠軍點，
   已永久收藏」），點不開、不會播。三個候選：
   A＝那行變可點按鈕、點開才播重演（玩家自選，不打斷結算節奏）；
   B＝結算流程走到那一步時自動插播一次重演（儀式感強、但每次結算都被迫看）；
   C＝兩者皆有（自動播一次＋典藏區可重看）。
   實作端傾向 A（不強迫、可重看，符合「畢業結算已經很長」的節奏保護）；
   顯示哲學沿用：無資料時入口不出現（不給看空欄）。
5. **小白事件二位置示意**：吃引擎的哪一層——A＝全重演那次撲球（需要事件二觸發時
   也錄 VCR，資料側新增）；B＝示意圖層（地板畫撲球路徑與空出的區域，靜態圖不重演）。
   實作端傾向 B：事件二的敘事點是「位置讓出來了」，示意圖比重演更聚焦，
   且不用為劇情事件加錄製鏈。
6. **同場設計題 A｜攻擊瞄準點/描線機制**（07-28 入卷）：簡化模式攻擊只選區、
   無精準落點控制——咬線演出上線後「敢選線」有了獎勵，但「瞄多準」仍是散佈決定。
   要不要加、怎麼加不變難？候選：①區內二段微調（點區後拖一下）②長按拉條
   ③維持現狀（選區＝夠了，精準留給屬性成長）。動 sim 決策面＝需重跑平衡治具。
7. **同場設計題 B｜憲法 Q7 位置驗證開放——正式結案確認**：Q7 結案定義＝
   「五位置工程完成＋至少 1-2 位置驗證開放」；現況四位置已版本級全開（07-27 拍板）
   ＋五位置招牌演出交付（4.5B 追加條 C「手感即演出」備料完成）。
   會議確認：Q7 就此關卷？還是保留「逐位置試玩驗證」儀式感（開放已既成，僅補驗）？
8. **平衡帶重校準時機**：卡死修復後決賽帶 23%→29%（n=300，如實記錄）——
   本輪要不要順手校準難度，還是等多屆實玩體感（滾動中）？
