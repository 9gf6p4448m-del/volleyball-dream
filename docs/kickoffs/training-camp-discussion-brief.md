## 三、待裁題 1：默契的加成，各位置分別是什麼

**背景**：`trust` 是**二傳對攻擊手的信任**，不是隊友之間的關係。
所以「跟隊友練 → 提高他的 trust」對玩家**沒有好處**（他更常拿球＝你更少拿）。加成對象必須重新定義。

**各位置在組合攻擊裡的角色**（見共用事實層 §三）：

| 位置 | 現況 | 「默契」最自然的加成方向（**提案，待裁**） |
|---|---|---|
| **OH** | 交叉／時間差的主攻者 | 你與該隊友之間的**組合攻擊**更容易成立或更有效 |
| **OPP** | 時間差主攻者；夾塞主攻者（關閉中） | 同 OH |
| **MB** | **永遠是配合者／誘餌** | **「我把牆帶得更走」**——實測 MB 玩家有 **64.2%** 的球真的把攔網帶走了，但遊戲從來沒告訴他 |
| **S** | 下令的人 | 你與該攻擊手的**組合成功率**／或你讀對一傳品質的容錯 |
| **L** | **不在攻擊體系裡**（規則上不可攻擊） | 防守配合（既有 `digBias` 那條線） |

**要裁的**：
1. 上表的方向對不對？有沒有更好的切法？
2. **幅度**（策略數值，硬規則 3）——建議「先量再定」：先做機制、量出基準分佈，再定數字
3. 選幾個人？（一位＝敘事最重／兩位＝彈性／像成長點數那樣分配時數＝選擇最細但會變成試算表）

## 四、待裁題 2：戰術成功時，信任給誰

**Sawmah 的原始想法**：戰術成功得分 ⇒ **那位攻擊手**得到更多信任。

**風險**：**滾雪球**。得分者信任提高 → 更常拿球 → 更多機會跑戰術 → 更多信任。
專案有明確的反滾雪球原則（OH 身分案就是因為「在強勢位置疊信任雙倍＝往壟斷走」而否決了要球鈕）。

**變體（提案）**：**信任給配合者，不給得分的人。**

| 理由 | |
|---|---|
| 得分者已經有獎勵 | 既有的 `trustDyn+`（殺進加分）本來就會給他 |
| 誘餌的功勞在真實排球裡人人都知道 | 把牆帶走的那個人 |
| **天然反滾雪球** | 獎勵流向沒得分的人 |
| **直接解掉 MB 的體驗問題** | MB 當誘餌會被看見、會被回報 |

**要裁的**：給得分者／給配合者／兩者都給（幅度不同）？

## 七、教學要教什麼（設計時別忘的實測）

第二屆同時解鎖兩件事：**你會用**、**對手也會用**。
所以集訓不只要教「怎麼叫」，還要教「**怎麼防**」——否則玩家第二屆會突然被一堆看不懂的球打死。

⚠ 但有一個實測要納入考慮：**強隊的組合攻擊沒有比它自己的普通攻擊更會得分**
（天鷹 +1.5±1.4、鐵霧 +2.8±2.7，都分不出）。加成集中在**弱隊**（北原 +12.5±3.1、白浪 +10.2±2.9）。
⇒ 「被強隊的交叉打穿」在現有引擎下**體感上分不出來**。教學若依賴那個體驗，會落空。
