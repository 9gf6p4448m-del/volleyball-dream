現況事實：`directGame.js:216-359`（接球判定鏈）、`directReceiveAssist.js`、`directPractice.js:458-482`（固定步長迴圈）、`directControls.js:3,250`（動作選單）。

## 一、範圍

做：接球（高手、低手）改規則判定；魚躍改規則判定；快球慢動作（練習場限定、可關閉）；出手鍵依情境自動選「接球／魚躍」，下拉選單移到設定頁當「練習指定」。
不做：扣球、吊球、攔網、舉球、發球的判定改動（第二～五階段）。選單上的獨立「吊球」選項在第二階段處理（Q5）。

## 二、規則定義（實作依此，測試也依此）

- **判定時刻（各技術各自一個）**：球心往下穿過該技術觸球高度的第一個 tick。高手＝額頭 `overHeight`（1.02 身高）；低手＝`platformCueHeight`（0.6 身高，與倒數提示同一個高度）；魚躍＝球心離地 0.3 m。依序檢查：球先穿過額頭高度時檢查高手，不成立就等穿過平台高度時檢查低手，再不成立就等到 0.3 m 時檢查魚躍。任一項成立（含噴球）即結束，不再往下檢查。
- **位置**：該判定時刻球心到該技術接球點的水平距離 d（高手接球點＝額頭前方 `overForward`；低手＝前臂平台中心；魚躍＝低手接球點）。接球圈半徑沿用現值：低手 `underRadius`=0.5 m，高手 `overRadius`=0.35 m（P2 已裁）。撲救範圍＝以低手接球點為圓心，0.5 m < d ≤ 2.0 m（低手圈外再 1.5 m，P3 已裁）。接球不再有左右滑選方向，一律送往舉球區中央 `target`（P1 已裁：拿掉）。
- **時機**：按鍵時機偏差沿用現行的 `perfectTicks`／`goodTicks`／`windowScale(球速)`，以該技術的判定時刻為基準。窗外＝偏差超過 `goodTicks×windowScale`，不論超出多少一律算窗外。
- **結果**：
  - 圈內且時機在窗內 → 依時機分成完美／普通／差，送往舉球區。
  - 圈內但時機在窗外或沒按 → 噴球（Q3）。
  - 圈外、撲救範圍內且有按 → 魚躍。
  - 其他 → 沒接到。原因字串的優先序：站位（不在任何圈內）先於時機。
  - 判定順序：高手 → 低手 → 魚躍。
- **物理只管畫面**：接球與魚躍的結果不再由 `collideBody` 的碰撞決定。判定那一格要把球貼到手上（不可隔空），再依規則送出。身體的走位、跑速、起跳照舊由物理模擬。

## 三、驗收條件（每條都附「什麼樣的實作會讓它變紅」）

| 編號 | 條件（可機械判定） | 什麼樣的實作會讓它變紅 |
|---|---|---|
| R1 規則取代碰撞 | 案例組由實作者在舊碼上產生並列表：球在低手圈內、時機完美，但舊碼逐例印出的觸球部位是軀幹、大腿或上臂（不是前臂或手掌），至少 20 例（沿用 A22 在 v6 用過的真實路徑產法；A22a/b/d 已於 v7 退場，這裡只借它的產法）。新碼這些案例必須全部判成「完美」並送往舉球區（20/20 以上，100%）。另一組：取其中 10 例，只改身體轉身角度（`receiveTurn` 設 −30°、0°、+30° 三種），判定結果（等級、落點）必須逐值相同。 | 結果仍由膠囊碰撞決定（舊碼穿過空隙＝沒接到或亂彈）。 |
| R2 分級單調 | 用 `tools/receive-assist-probe.mjs chase`（固定網格、無隨機，n=2646；R2、R6、R8 用同一次跑出的資料）的每一筆觸球，按等級分組算落點到舉球目標的平均距離：完美 < 普通 < 差，而且三級各至少占觸球數 5%。 | 等級與落點誤差脫鉤，或某一級永遠不會出現。 |
| R3 噴球 | 自建案例組：球在低手圈內，(甲) 沒按 30 例、(乙) 按鍵偏差落在窗外 30 例（早晚各半，偏差取窗外 1～6 tick）。兩組每一例都要有觸球事件、標記為噴球，不能判成「沒接到」；每組各自落進舉球區的比例 ≤ 10%（分母＝該組例數）。 | 圈內沒按也送進舉球區，或直接穿身而過判成沒接到。 |
| R4 魚躍 | 自建案例組：球在撲救範圍內（0.5 m < d ≤ 2.0 m）且有按出手，至少 30 例 → 每例都自動朝球撲出，在球心離地 0.3 m 的判定時刻判定，等級最高只到「普通」（完美出現 0 次）。對同一組 10 種按鍵偏差，魚躍的平均落點誤差 > 低手接球的平均落點誤差。倒地後 42 tick（0.7 秒）內移動指令不改位置、出手指令不產生動作。d > 2.0 m 按出手 30 例：0 例救到。 | 魚躍能出「完美」、撲救範圍外也救得到，或倒地後立刻能動。 |
| R5 判定順序 | (甲) 球穿過額頭高度時已在高手圈內且時機在窗內 → 判高手，就算之後也會進低手圈。(乙) 邊界：d=0.49 m 判低手、d=0.51 m 且有按判魚躍，各 10 例。 | 優先順序顛倒，或圈邊界判錯邊。 |
| R6 不隔空 | 判定那一格，球面到手掌或前臂表面的距離 ≤ 0.05 m，比例 100%（R1 的案例組加上追球探針的全部觸球）。 | 球在遠處就被判定送出，畫面上是隔空接球。 |
| R7 失誤原因 | 每顆球結束時一定有非空的原因字串。「沒接到」要說明是站位（附公分與方向）或時機，兩者都不合格時寫站位；噴球要寫明「按太早／太晚／沒按」；魚躍要標明「魚躍」。 | 有一類結果沒有說明原因。 |
| R8 難度不退步 | 真人追球探針（新規則版，n=2646，全部案例當分母）：空接 ≤ 25%、碰網 ≤ 5%、舉球區 ≥ 34%（沿用 A23a 已簽的門檻，P4 已裁）。 | 新規則比現況更難接。 |
| R9 慢動作 | 純函式 `slowMotionScale(state)`，不依賴 three。快球（≥ 13 m/s）、離「下一個會成立的判定時刻」≤ 0.4 秒（用 `receiveContactEta`）、人在接球圈或撲救範圍內 → 0.5；其他情況 → 1。慢球、人不在範圍內、設定關閉 → 1。**同一卷錄影開與關慢動作，sim 事件序列逐位元相同**。練習場的瀏覽器治具要實測：強力發球時畫面速率確實降到 0.5，關閉後恢復 1。 | 慢動作改到 sim 的時間（判定因此不同），或在不該觸發時觸發。 |
| R10 情境出手 | 純函式 `contextAction(state)` 回傳 `receive`／`dive`／`null`。設定頁「練習指定」預設＝自動：自動時出手動作＝`contextAction ?? 'receive'`；指定為某動作（扣球、舉球、攔網等）時一律用指定動作。出手鈕的文字與 sim 實際執行的動作每個 tick 都相同（比照 pass-lock 的做法）。手機直式治具：主畫面不再出現動作下拉選單。 | 按鈕顯示的動作和實際執行的不同，或主畫面仍要切選單。 |
| R11 決定論 | 含接球、噴球、魚躍、慢動作的錄影，整卷重播與中途還原逐位元相同（比照 A5）。 | 規則判定引入了不決定的狀態。 |
| R12 全套綠 | `npm test` 除第四節核准退場的測試外全綠；四個瀏覽器治具 PASS；部署後用 `--delivery` 對線上版 PASS，公開站版本字串為 `direct-v8.1`。 | — |

鑑別力要求：R1、R3、R4、R6 要先在**舊碼**（`b2e2a86`）上跑，且必須因為行為斷言而紅；R9、R10 的相等性斷言要附活性證據（慢動作觸發次數 > 0，情境切換到魚躍的次數 > 0）。
