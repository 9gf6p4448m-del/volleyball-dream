## 一、裁定的實作內容

read 的起跳時鐘：

> **起跳 tick ＝ 預測擊球 tick**（前置量 0）
>
> 該值在「**二傳觸球 ＋ 該攔網手自己的反應延遲**」那一刻**取樣一次並鎖存**，之後不重算。
> 鎖存只鎖**起跳時鐘**；瞄準 x 仍逐 tick 重算（改判付重新踩定代價，沿用既有規格）。

- **零新常數**：沒有位移量、沒有新門檻。
- **commit 不動**（v3 裁定書 R3）：仍吃助跑下降沿。
- **兩人格不再共用起跳訊號**——這是路 D 撤銷條文的實作面。

### 1.1 為什麼不是 v3 裁定書 R2 的原形式

R2 原形式＝`預測過網 tick − 跳躍窗長/2`。**「預測過網 tick」實測不可導**：

- 幾何上 `t = −z/vz` 有正解的比例 67.9%，但**解出來的值誤差 p50 117／280 tick**，後排 **0/57** 無正解
- 成因：取樣那一刻球還在**二傳的球路**上，那組速度描述的是「二傳的球慢慢飄過網」；
  球會**先被扣走、換一組全新速度**才真的過網

⇒ R2 自己的退路條款（「只有預測擊球 tick 可導 ⇒ 不得用固定位移補差 ⇒ 停下回報」）觸發，
回報後由本裁定書改寫目標。

## 三、本輪的護欄與代價

### 3.1 款 3 是靠一個偏誤撐著的（必須知道）

read 對快攻來不及，機制是：**快攻的預測擊球 tick 系統偏晚 +7～+9 tick**（sd 0.76），
而快攻「擊球→過網」的飛行段只有 **≈6 tick**。偏晚 > 飛行段 ⇒ read 在球過網之後才離地。

實測起跳 `set+40`、球過網 `set+38` ⇒ **read 對快攻在球過網後 2 tick 才起跳**，
過網時窗沒開的比例 75.3%。這正是款 3 要的行為。

**⇒ 任何日後改善擊球點預測精度的改動都會打穿款 3。**
護欄已上膛：`tests/block-persona.test.mjs`
「B1 回歸閘：read 對快攻的預測擊球 tick 仍偏晚（款 3 的載體不得消失）」
——中位數低於 6 tick（＝快攻飛行段實測中位數）即轉紅。實測中位數 8，餘裕 2 tick。

### 3.2 新失衡（本輪不處置，登記為觀察項）

改完後 read 在兩翼（90.4% vs commit 19.4%）與後排（75.0% vs 0.0%）**全面壓過 commit**，
只在快攻輸。本輪禁止任何平衡校準（v3 §五），故**不動**。
下一輪若要處置，對象是 commit 的起跳訊號（非 blind 計畫全部在 `set+0` 起跳，
而攔網窗只有 48 tick），不是 read。

### 3.3 這算不算回到十-2 譴責的「對扣球事件零延遲反應」

**機制層：不是。** read 讀的是二傳出手後球的拋物線，在「二傳觸球＋反應延遲」取樣**並鎖存**，
早了 50–80 tick；舊行為讀的是「扣球已經發生」這個事件本身。
**觀感層**：前置 0 下球過網時兩翼的手還在上升、後排已在下降、快攻多半還沒離地
⇒ 動作看起來**偏晚**，與舊行為「球一出手就準時拔起」的觀感簽章不同。
